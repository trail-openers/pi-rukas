| `PI_ENSEMBLE_LEAN_SPEC_INTAKE` | unset → `require` | **Where a lean run's contract comes from when its issue has no `pi-spec v1` block.** `require` (the shipped default, and byte-for-byte the behaviour every run before this knob had) declines the issue exactly as before: one comment naming `no pi-spec v1 block`, `not-ready` at exit 11. `derive` sends the ticket to ONE bounded read-only `explore` child, which replies with a `pi-spec v1` block the run validates as though an author had written it — the same `readiness()` gate, the same `size: "L"` refusal, the bullets mapped by the shared `pi-spec-map.ts` `/plan` files from, so a derived contract cannot be bounded or neutralised differently from a filed one. Accepted values are exactly `require` and `derive`, and an invalid value on EITHER side (env or `.pi/work.json`) is a refusal naming the values, never a silent fallback to the default — a `derve` that quietly became `require` would decline the tickets the operator set the knob to take. Read at call time, so the env can be set per run, and overridden for one headless run by `work-lean --spec-intake <mode>` (an invalid flag value is an argument error, and the value is written to the env as late as the parser allows because `process.env` is process-wide). Three shapes stay `require`'s refusal in both modes, because in each the issue is at fault and no model call is billed for it: no block at all, a blank body, and a block that is present but MALFORMED (the author wrote a contract wrong; a model writing a better one over their mistake would hide the defect). A derivation that FAILS — dead child, fired budget, empty or unparsable reply, contract that is not ready — is a handback at exit 10 naming its own cause (`ready`'s `infra` verdict), not a decline: the issue did nothing wrong, and that difference is what keeps the run retryable. The child asks for at most 8 criteria (the count at which the mapper still calls the change `M`), so a 9-criterion reply takes the honest size-`L` refusal with the rendered block quoted — the list is never truncated to satisfy the gate. The contract is persisted on the run (`derivedSpec`, validated on both write and load) and every step reads it through `specFor`; `ready` posts it to the issue as a fenced block naming the drafting model, and the PR body prints `spec: derived`, both skipped when `PI_ENSEMBLE_HANDOFF_CHANNEL=host` owns the channel. Ceiling: the `budgets.derive` row. Read at call time, per step.
